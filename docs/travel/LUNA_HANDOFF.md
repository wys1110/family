# Luna에게 전달할 구현 요청

`wys1110/family`에 가족 여행 탭을 구현해 주세요. 설계 원문은 함께 제공한 `TRAVEL_TAB_SPEC.md`입니다. 전체를 먼저 읽고 PR 1부터 작은 단위로 구현합니다.

1. 최신 main과 AGENTS.md를 확인하고 별도 브랜치를 만드세요. 현재 설계 기준 main은 `01f3844b090947f93e3585243f2ee25f9ef61dc1`입니다.
2. 기존 vanilla JS/PWA/Supabase 구조와 Nova 디자인을 유지하세요. config.js, deferred-tabs.js, tab-emojis.js, app.js의 switchView 래퍼 체인을 먼저 조사하세요. 여행 모듈과 지도는 지연 로딩합니다.
3. 여행 생성 → 항공·숙소 후보/외부 예약 → 날짜별 일정·지도 → 준비·추억 흐름을 구현하세요. 지도에서 하루/전체 동선을 한눈에 보고 장소 카드와 핀이 연동되어야 합니다.
4. 1차는 외부 검색/예약 이동과 수동 후보·예약 등록입니다. 제휴 승인된 API가 있을 때만 실시간 가격 검색을 추가하세요. 링크 클릭을 예약 완료로 처리하지 마세요.
5. PR 1(화면·데모), PR 2(가족 저장·권한·기록), PR 3(지도·예약 이동) 순서로 진행하세요. 공급자 승인이 필요한 PR 4는 독립시키세요. 미연동 상태를 완료로 포장하지 마세요.
6. 다른 가족 데이터 접근, 이중 예약 일정, 오래된 검색 응답, 시차, 가격 합산, 동시 편집을 검증하세요. 날짜/순서 수정으로 실제 예약 시간을 바꾸거나 기존 데이터를 임의로 삭제하지 마세요.
7. 설계의 테스트 12개와 기존 테스트를 실행하고, 모바일/PC 및 밝음/어두움 실제 화면을 제시하세요. 새 여행 모듈 때문에 기존 탭 전환·첫 실행이 느려지지 않는지도 확인하세요.
8. 키·제휴 승인 없이 할 수 있는 작업은 먼저 끝내세요. 유료 API 활성화·실제 예약·결제·운영 DB 변경·공개 배포는 실행 직전 사용자 확인을 받으세요. 시크릿은 프런트엔드·문서·Git에 저장하지 마세요.

이번 요청에서 원하는 결과는 동작하는 여행 계획 기능과 검증 결과입니다. 실시간 API가 미승인이라면 그 부분만 분명히 남겨 두세요. React/Next.js 전면 전환이나 자동 결제 시스템 구축은 하지 않습니다.
