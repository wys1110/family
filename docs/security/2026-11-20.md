## 변경 코드와 권한 검증

- **달력 자동 새로고침.** 30초 간격과 화면 복귀 때 현재 가족 ID로 일정을 읽는다. 조회 전·후에 클라이언트·사용자·가족·부트스트랩 세대를 확인하고, 페이지를 넘기는 도중에도 같은 조건을 검사한다. 로그아웃, 사용자·클라이언트·가족 교체, 세대 변경, 인증 전환 중 늦게 도착한 응답 여섯 조건을 합성 VM에서 실행해 화면과 일정을 교체하지 않는 것을 확인했다. 편집·삭제·일괄 저장 도중 먼저 시작한 조회가 로컬 변경을 덮어쓰는 기존 회귀도 통과했다. `app.js:574-624`, `family-data.js:4-20`, `family-auth.js:100-128`.
- **시작·지연 로딩.** 시작 화면은 메뉴·스타일·인증 초기화가 끝날 때까지 `aria-busy`, `inert`, 숨김 상태를 사용한다. 지연 로딩 완료 뒤에도 요청 ID와 계정·가족 문맥을 확인한다. 로딩 오류는 `textContent`로 표시하고 자산 주소는 고정 모듈 목록에서 구성한다. 배포 대상에서 디자인 미리보기 파일 네 개를 추가로 제외했다. `index.html:14-23,84`, `app.js:292-298,418-425,1143-1149`, `deferred-tabs.js:26-33,50-100`, `scripts/prepare-capacitor.mjs:7-10`.
- **RLS 합성 회귀.** 작성자 위조와 다른 가족의 조회·변경을 차단하고, 두 가족에 모두 속한 사용자도 기록을 다른 가족으로 옮길 수 없는 것을 기존 마이그레이션 테스트로 확인했다. 비공개 반복 할 일의 작성자 제한, 공유 수면 종료·취소의 타 가족·없는 ID 응답 통일, 알림·사용량 RPC 접근 검증도 통과했다. 운영 DB의 배포된 정책을 직접 조회한 결과와는 구분한다. [Supabase RLS 지침](https://supabase.com/docs/guides/database/postgres/row-level-security)

## 의존성과 기존 미해결

- **DEP-01 / 기존 Moderate.** 전체 잠금 파일 검사는 Critical 0, High 0, Moderate 영향 패키지 6개로 전일과 같았다. 전이 영향이 포함된 수치이며 `--omit=dev`는 모든 심각도 0이었다. 기존 `glob`, `minimatch`, `uuid` 공지의 심각도·갱신일은 동일했고, 전일 철회된 `picomatch` 공지도 철회 상태다. [glob](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) · [minimatch](https://github.com/advisories/GHSA-g3hv-75wg-m249) · [uuid](https://github.com/advisories/GHSA-w5hq-g745-h8pq)
- **HARDEN-01 / 기존 Medium.** 공개 HTML의 Supabase JS CDN 참조는 `@2`로 유지된다. 오늘 해당 URL의 응답 버전은 `2.119.2`였고 npm 패키지의 `auth-js`도 `2.119.2`였다. 공식 릴리스는 Storage 객체 요청 URL의 경계 검증 변경을 포함한다. 정확한 버전 고정·SRI·CSP 보강은 기존 추적 항목이다. `index.html:623`. [Supabase JS 2.119.2 릴리스](https://github.com/supabase/supabase-js/releases/tag/v2.119.2) · [11월 7일 보고서](2026-11-07.md)
- **Storage SDK 변경 검토.** 새 URL 검증과 앱의 생성 경로를 합성 비교해 성장 사진·월페이퍼·백업 경로가 지정 버킷에 남는 것을 확인했다. 백업 내보내기의 기존 가족 ID 접두사 검사만으로는 `..` 경로를 제거하지 못하지만 새 SDK는 버킷 밖으로 정규화되는 요청을 전송 전에 거절한다. 같은 버킷 안의 다른 가족 접근은 서버 RLS가 제한한다. 실제 권한 우회나 정보 유출은 이번에 재현하지 않았다. `family-backup-media.js:19-20,66-77`, `app.js:805-816,2708-2729`.
