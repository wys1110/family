## 일정과 접근 로그

- **신규 · Low · 미해결.** 기존 일정을 수정하거나 삭제할 때 다른 기기의 변경을 보호하기 위해 이전 제목·구성원·메모 등을 PostgREST 필터로 보낸다. 이 값은 요청 URL에 들어간다. Supabase는 API 게이트웨이 로그의 요청 URL에 쿼리가 포함될 수 있다고 설명한다. 이 프로젝트의 원문 보존 여부와 열람자는 확인하지 않았다. 후속 수정에서는 구버전 앱의 동시 편집 보호를 유지하면서 일정 내용을 URL에서 제거할 수 있다. 예를 들어 DB가 모든 쓰기에서 갱신하는 버전 값으로 충돌을 판정하는 방법이 있다. [일정 저장·삭제 구현](../../app.js) · [PostgREST 필터](https://docs.postgrest.org/en/stable/references/api/tables_views.html#horizontal-filtering) · [Supabase 로그 필드 안내](https://supabase.com/kb/troubleshooting/discovering-and-interpreting-api-errors-in-the-logs-7xREI9)

## 자장가와 의존성

- 자장가 선택은 세 개의 공개 음원 ID로 제한된다. 기기에는 선택한 ID를 저장하며, 새 버퍼링·화면 복귀 처리는 재생 상태와 안내 문구를 갱신한다. 서비스 워커의 캐시 대상에 음원과 인증 API는 없다. 모의 재생 테스트가 통과했고 실제 아이폰 잠금 중의 재생은 확인하지 않았다. [재생 구현](../../lullaby.js) · [서비스 워커](../../service-worker.js) · [재생 회귀 테스트](../../test/continuous-lullaby.test.js)
