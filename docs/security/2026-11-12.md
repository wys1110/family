## 발견과 미해결

- **SESSION-01 / Medium — 일정 편집창에서 영향 범위 추가 확인.** 실제 인증 이벤트 처리, 데이터 초기화와 저장 함수를 모의 DOM·Supabase로 실행했다. 같은 브라우저에서 일정 편집창을 열어 두면 로그아웃과 다른 가족 계정 로그인 뒤에도 기존 일정 메모가 남았다. 작성 중이던 새 일정을 전환 후 저장하면 이전 초안이 새 가족과 새 계정 ID를 담은 저장 요청에 들어갔다. 이 문제는 이전에 확인한 성장 기록 편집창과 같은 계정 전환 경계에 있다. `index.html:74,338`, `app.js:266-278,349-415,958-962,1062-1067,1527-1553,1594-1617`. [11월 10일 보고서](2026-11-10.md)
- **SLEEP-01 / Medium — 다른 가족의 진행 중 수면 종료 차단.** 합성 DB에서 두 가족에 실제 성장 기록 정책과 공유 수면 마이그레이션을 적용했다. 진행 중인 세션 UUID를 이미 아는 다른 가족의 인증 사용자가 자기 가족에서 합법적인 성장 기록 쓰기를 했을 때 식별자가 충돌할 수 있었다. 충돌 중에는 원래 가족의 정상 종료 요청 두 번이 기본 키 충돌로 롤백돼 수면 상태가 계속 진행 중이었다. 원래 가족은 상대 행을 조회하거나 삭제할 수 없었고, 대조군에서는 충돌이 없는 상태에서 종료에 성공했다. 영향 범위는 식별자가 알려진 진행 중 세션이다. 전 구성원이 탈퇴 전 확인한 세션 ID를 가지고 있는 경우를 합성 환경으로 모델링했다. `supabase/schema.sql:64-88,194-198,238-241`, `supabase/migrations/20261031094052_shared_family_sleep.sql:70-85`. [PostgreSQL 행 수준 보안](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)
