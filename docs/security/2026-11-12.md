## 사용자 직접 요청에 따른 수정

- 정기 점검을 재실행하지 않고, 보고된 일정 단일 편집창의 계정 전환 문제와 공유 수면 종료 충돌을 수정했다. 사용자 작업 브랜치는 보존하고 `ef33b43`에서 별도 작업 트리를 사용했다.
- **SESSION-01(단일 일정 편집창):** 창을 열 때 사용자·가족·클라이언트·데이터 로딩 세대를 고정한다. 계정 전환 및 데이터 재조회 시작 시 창을 닫고 입력값·숨은 ID를 지운다. 저장/삭제·인증 재시도와 늦은 응답은 해당 문맥에서만 처리하며 저장과 삭제의 중첩도 차단한다. 동일 사용자 토큰 갱신은 초안을 유지한다.
- **SLEEP-01:** 공개된 세션 UUID를 새 성장 기록 ID로 재사용하지 않는다. 서버 생성 ID와 세션의 연결을 종료와 함께 원자적으로 저장한다. 삭제 시 연결을 해제하고, 재시도 조회도 세션 연결과 기록을 하나의 SQL 스냅샷에서 읽는다. 다른 가족의 동명 ID 기록은 수정하거나 삭제하지 않는다. 다른 구성원의 화면은 실제 연결된 기록 ID를 조회한다.
- **SLEEP-02:** 종료·취소에서 다른 가족/아기의 세션과 없는 세션은 같은 오류로 응답한다. **시작 요청의 UUID 존재 여부 구분은 이번 변경 범위 밖이며 미해결**이다.
- 기존 보고서에 언급된 성장 기록 편집창과 이번 검토에서 확인한 일정 일괄 추가창은 단일 편집창 수정과 별개로 남아 있다. 전체 편집창의 격리가 완료됐다고 보지 않는다.
- 합성 회귀는 계정 전환 전/저장 중/인증 복구 중/삭제 중, 늦은 응답, 실패 후 재시도, 토큰 갱신, 정상 삭제 위치 복원을 검사한다. DB 회귀는 실제 성장 기록 RLS 아래 다른 가족의 ID 선점, 종료 재시도, 삭제 뒤 같은 ID 재사용, 삽입 실패 롤백, 기존 이력·진행 중 세션·시작 별칭 보존을 검사한다. 기존 10월 마이그레이션 회귀는 과거 설치 동작을 별도로 유지한다.
- 운영 함수 정의가 보고된 구버전과 일치함을 읽기 전용으로 확인했다. 운영 개인 행을 재현 테스트에 사용하지 않았다. CI·웹 배포·운영 DB 적용은 PR과 배포 결과로 별도 확인하며, 실제 가족 계정 두 대와 설치된 네이티브 앱 검증은 합성 검증에 포함되지 않는다.
