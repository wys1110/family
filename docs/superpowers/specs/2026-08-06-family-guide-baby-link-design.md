# 준비·육아 가이드 아기 프로필 연동 설계

## 목표

가이드 탭이 성장 탭에서 선택된 아기 프로필을 기준으로 현재 단계를 계산하고, 아기별 체크리스트 상태가 섞이지 않도록 한다.

## 범위

- `activeBabyId`를 가이드의 기준 프로필로 사용한다.
- 아기 출생일을 산후·영아·유아 단계 계산에 사용한다.
- 출산 전에는 기존 가이드의 예정일 입력을 유지한다.
- 예정일과 출산일 입력은 선택한 아기 프로필과 동기화하되, 출산일이 없는 프로필은 사용자가 입력할 수 있다.
- 완료·숨김 카드 ID를 아기별로 저장한다.
- 아기 전환 이벤트(`familybabychange`)에서 가이드를 즉시 다시 렌더링한다.
- 아기 프로필이 없거나 선택되지 않은 상태에서는 기존 전국 공통 가이드를 보여준다.

## 데이터 흐름

1. 가이드 초기화 시 `activeBaby()`로 현재 아기를 읽는다.
2. 가이드 설정은 기존 저장 키를 유지하되 `profiles[아기ID]` 아래에 기준일·지역·상태를 둔다.
3. 기존 단일 설정 데이터가 있으면 현재 아기 프로필로 한 번만 읽어 호환한다.
4. 렌더링 시 선택 아기 출생일을 우선 사용하고, 가이드에 저장된 예정일을 출산 전 기준으로 사용한다.
5. 날짜·지역·완료·숨김 변경은 현재 아기 프로필에만 저장한다.
6. `familybabychange` 수신 시 현재 프로필을 바꾸고 단계·목록·완료 수를 갱신한다.

## UI

- 설정 영역에 현재 기준 아기 이름을 표시한다.
- 날짜 필드는 현재 프로필의 출생일을 읽기 전용으로 표시한다.
- 출산 전 기준이 필요한 경우에만 예정일 입력을 노출한다.
- 기존 지역·필터·출처 UI는 유지한다.
- 아기 전환은 성장 탭의 기존 프로필 선택기를 사용하며 가이드에 중복 선택기를 추가하지 않는다.

## 오류·경계

- 출생일이 없는 아기는 예정일/기준일 설정 전 상태로 처리한다.
- 현재 아기 ID가 삭제·아카이브된 경우 빈 프로필 상태로 안전하게 돌아간다.
- 로컬 저장 실패 시 현재 화면 상태만 유지한다.
- 아기별 상태 키가 없으면 빈 배열로 시작한다.
- 가족·아기 데이터는 기존 저장 범위와 Supabase RLS 경계를 벗어나지 않는다.

## 검증

- 데이터 API 테스트: 프로필 출생일 우선순위·단계 계산.
- 가이드 소스 테스트: active baby 연동, 아기별 저장 구조, 전환 이벤트.
- 기존 가이드 데이터·필터 테스트.
- 관련 Vitest 전체 실행 후 결과 기록.
