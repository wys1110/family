# Family 3분 시작 체크리스트 설계

## 목적

처음 가족 공간을 만든 사용자가 아기 등록, 첫 돌봄 기록, 보호자 연결까지 끝내고 가족 인수인계를 바로 사용할 수 있게 한다. 체크리스트는 팝업이 아니라 일정 화면 히어로 아래의 짧은 카드로 제공한다.

## 선택한 접근

1. **저장된 진행 상태**: 초대 전송 여부를 따로 저장한다. 전송과 실제 참여가 달라 신뢰할 수 없고, 새 테이블이 필요해 제외한다.
2. **행동 완료만 표시**: 기록을 추가할 때마다 임시 진행 상태를 바꾼다. 새로고침·다른 기기에서 일관되지 않아 제외한다.
3. **실제 가족 데이터에서 계산**: 아기, 현재 아기의 첫 기록, 가족 구성원 수를 읽어 완료를 계산한다. 기존 RLS 범위 안에서 정확하며 새 데이터 모델이 필요 없어 채택한다.

## 사용자 경험

- 카드 제목은 `가족 시작하기`다.
- 순서는 항상 `아기 등록` → `첫 돌봄 기록` → `보호자 연결`이다.
- 완료 항목은 체크 상태로 보이고, 다음 미완료 항목 하나만 버튼으로 제공한다.
- 아기가 없으면 `아기 등록하기`가 기존 아기 프로필 대화상자를 연다.
- 아기는 있으나 현재 아기 기록이 없으면 `첫 기록 남기기`가 기존 수유·이유식 빠른 기록을 연다.
- 소유자이고 실제 구성원이 한 명이면 `보호자 초대하기`가 기존 계정·초대 화면을 연다. 링크 전송은 사용자가 기존 공유 버튼에서 확정한다.
- 일반 구성원은 초대를 보낼 수 없으므로 `가족 초대를 기다리는 중` 안내만 본다.
- 세 단계가 모두 완료되면 카드를 렌더링하지 않는다.

## 데이터·동기화

- `state.babies`, `state.activeBabyId`, `state.growthEntries`만으로 아기와 첫 기록 단계를 계산한다.
- 원격 로그인 가족만 현재 `household_id`의 `household_members` 수를 읽는다. 기존 구성원 조회 RLS가 적용되므로 다른 가족 구성원은 조회하지 않는다.
- 데모 가족은 이미 공동 가족·기록이 있는 상태로 간주해 카드를 숨긴다. 오프라인 개인 기록은 구성원 한 명으로 계산한다.
- 비동기 구성원 수 응답은 요청 당시의 `household_id`가 아직 현재 가족일 때만 반영한다. 두 번째 구성원이 아직 없거나 일시 조회 실패일 때만 30초 뒤 다시 확인하고, 완료되면 즉시 중단한다. 화면이 다시 보이면 즉시 한 번 확인한다.
- `familycontextchange`, `familybabychange`, `family:growth-entry-saved`, `family:growth-entry-deleted`, 새 `family:baby-saved` 이벤트에서 카드가 갱신된다.

## 범위와 안전 기준

- DB 마이그레이션, 초대 전송 기록, 분석, 의료 판단을 추가하지 않는다.
- 다른 가족의 아기·기록·구성원 수를 UI 또는 요청에 섞지 않는다.
- 버튼 최소 높이는 44px, 390px 모바일 화면에서 가로 스크롤·글로벌 FAB 겹침이 없어야 한다.
- 색상은 기존 테마 토큰만 사용해 화이트·다크 모드 모두 유지한다.

## 검증

- 단위 테스트는 단계 계산, 활성 아기 기록 범위, 소유자/일반 구성원 행동, 컨텍스트 경합 방어, 모듈 등록을 검증한다.
- 전체 테스트, 정적 검사, diff 검사를 통과한다.
- `?demo=1`의 390×844와 430×932에서 카드 위치·터치 영역·가로 넘침을 확인한다.
