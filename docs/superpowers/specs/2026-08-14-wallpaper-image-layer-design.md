# 일정·성장 월페이퍼 이미지 레이어 설계

## 문제와 목표

현재 월페이퍼는 카드의 CSS 배경으로 렌더링된다. 사진을 `contain`으로 바꿔도 일정 카드의 기본 가족 캐릭터와 성장 카드의 넓은 콘텐츠 영역이 사진 위에 남아 실제 사진을 가린다. 일정·성장 카드 모두에서 원본 비율을 유지한 사진 전체가 보이는 구조로 바꾼다.

## 선택한 방식

- CSS 다중 배경 대신 카드 안에 장식용 `<img class="wallpaper-image">` 레이어를 둔다.
- 이미지는 카드 전체를 기준으로 `object-fit: contain`과 `object-position: right center`를 사용한다. 사진 비율 때문에 생기는 여백은 카드 기본 배경으로 채운다.
- 가독성용 그라데이션은 이미지와 콘텐츠 사이의 별도 레이어로 유지한다.
- 월페이퍼가 있을 때 일정 카드의 기본 가족 캐릭터는 숨긴다. 가족 이름 칩과 실제 콘텐츠는 유지한다.
- 성장 카드도 동일한 이미지 레이어를 사용하되, 텍스트와 돌봄 요약은 이미지 위의 콘텐츠 레이어에 둔다.
- 사진 변경·삭제 버튼은 항상 가장 위에 두고 기존 권한 및 저장 흐름을 그대로 사용한다.

## 구성과 데이터 흐름

`renderWallpapers()`가 각 월페이퍼 카드의 이미지 요소를 찾아 서명 URL을 `src`에 설정하고, URL이 없으면 요소를 숨긴다. 기존 `has-wallpaper` 클래스는 텍스트 대비, 기본 캐릭터 숨김, 버튼 표시 상태를 제어한다. 업로드·DB 메타데이터·가족별 경로 검증·서명 URL 발급 로직은 변경하지 않는다.

이미지 로딩에 실패하면 이미지 요소만 숨기고 카드 기본 디자인과 콘텐츠를 그대로 보여 준다. 다음 데이터 동기화에서 새 서명 URL을 받으면 다시 표시한다.

## 변경 범위

- `index.html`: 일정·성장 카드에 장식용 이미지와 스크림 레이어 추가
- `app.js`: CSS 변수 대신 이미지 `src`와 표시 상태를 갱신
- `family-wallpapers.css`: 이미지·스크림·콘텐츠 적층 및 기본 캐릭터 숨김
- 관련 회귀 테스트와 정적 자산 버전 갱신

## 제외 범위

- 사진 자르기, 확대, 초점 위치 편집 기능
- Supabase 테이블, RLS, Storage 경로 및 기존 가족 데이터 변경
- 카드 정보 구조와 카드 높이의 전면 재설계

## 검증 기준

- 세로·가로 사진 모두 원본 비율을 유지하며 카드 안에 전체가 표시된다.
- 월페이퍼가 있는 일정 카드에서는 기본 가족 캐릭터가 사진을 가리지 않는다.
- 성장 카드의 텍스트와 조작 버튼은 사진보다 위에 있고 읽을 수 있다.
- 이미지 로드 실패 시 깨진 이미지 아이콘 없이 기본 카드로 복구된다.
- 월페이퍼 저장·교체·삭제, 가족별 경로 검증, 전체 정적 검사와 테스트가 통과한다.
- 모바일 폭에서 실제 이미지 요소의 `object-fit: contain`과 적층 순서를 브라우저로 확인한다.
