# 가족 준비·육아 가이드 설계

## 목표

예정일/출산일과 선택 지역을 기준으로 출산 준비, 신생아 돌봄, 건강 일정, 외출·여행, 어린이집·유치원 신청 정보를 한 탭에서 확인한다. 모든 정보 카드에 공식 출처와 확인일을 표시하고, 사용자가 필요 없는 카드는 화면에서 숨길 수 있게 한다.

## 사용자 경험

- 새 상단 탭 `가이드`를 추가한다.
- 첫 화면에는 기준일 설정(예정일 또는 출산일), 지역 선택(시·도/시·군·구), 현재 단계, 가까운 할 일을 보여준다.
- 기준일이 없으면 개인화 D-day를 계산하지 않고 `기준일을 설정하면 맞춤 일정이 표시돼요`만 보여준다.
- 지역이 없으면 전국 공통 카드를 보여주고, 지역을 선택하면 해당 지역 카드가 우선 노출된다.
- 단계/카테고리 필터와 `전체/진행 전/완료/숨김` 상태를 제공한다.
- 각 카드에는 제목, 시점, 실행 요약, 주의 문구, 출처명, 원문 링크, 마지막 확인일이 있다.
- 사용자가 숨긴 카드는 가이드 화면에서만 숨기며 원문 데이터나 가족 일정·성장 기록은 삭제하지 않는다.

## 정보 범위

1. 출산 전 D-day 준비
2. 산후 초기·신생아
3. 생후 월령별 돌봄
4. 예방접종·영유아 건강검진
5. 외출·여행 준비
6. 출산·육아 준비물
7. 어린이집 입소대기
8. 유치원 입학

의료·여행 정보는 보편적 단정 대신 확인 항목과 공식 안내 링크를 제공한다. 증상 판단, 진단, 약물·제품 효능 추천은 만들지 않는다. 제품 카드는 안전·필수 확인 항목만 다루며, 상업적 추천은 제외한다.

## 출처 정책

- 1차 출처 우선: 질병관리청 예방접종도우미, 보건복지부, 교육부, 국민건강보험공단, 임신육아종합포털 아이사랑, 선택 지역 지자체.
- 카드마다 `sourceName`, `sourceUrl`, `checkedAt`을 필수로 둔다.
- 출처가 없는 문장은 배포 데이터에 넣지 않는다.
- 정책·신청 일정은 고정 날짜로 단정하지 않고 공식 포털의 현재 공고를 확인하도록 안내한다.
- 출처 링크가 깨져도 카드 본문은 성공으로 간주하지 않고 `출처 확인 필요` 상태를 표시한다.

## 데이터·보안

가이드 데이터는 정적 모듈로 배포한다. 사용자 입력은 `family-guide-settings-v1`에만 저장한다.

```js
{
  dueDate: "YYYY-MM-DD | null",
  birthDate: "YYYY-MM-DD | null",
  region: { sido: "", sigungu: "" },
  hiddenCardIds: [],
  completedCardIds: []
}
```

예정일/출산일/지역은 가족 일정·성장 기록·검색 인덱스와 섞지 않는다. 로그인 사용자는 household 단위 키를 사용하고 데모는 로컬 키를 사용한다. 민감한 건강 상세정보는 저장하지 않는다.

## 모듈 경계

- `family-guide-data.js`: 출처 필수 정적 카드 데이터, 지역·단계 계산 순수 함수
- `family-guide.js`: 설정 저장, 카드 필터/완료/숨김, 기준일 계산, 탭 DOM 연결
- `family-guide.css`: 기존 테마 토큰과 모바일 터치 영역 사용
- `test/family-guide.test.js`: 출처 필수 검증, D-day/생후 단계 계산, 지역 필터, 숨김·완료 상태 검증
- `index.html`, `app.js`, `config.js`: 탭 등록과 뷰 전환만 수정

## 실패·경계 처리

- 날짜가 없거나 잘못된 경우 개인화 계산을 중지하고 설정 안내를 표시한다.
- 출산 전/후 날짜가 모두 있으면 출산일을 우선 사용하고, 모순 날짜는 저장하지 않는다.
- 지역 카드가 없으면 전국 공통 카드로 폴백한다.
- 모든 카드에 출처 필드가 없으면 테스트가 실패해 배포를 막는다.
- 링크는 새 탭으로 열고 `noopener,noreferrer`를 적용한다.

## 검증 기준

- 가이드 탭이 캘린더·성장·설정 등 기존 화면을 깨지 않고 전환된다.
- 기준일/지역을 입력하면 화면 새로고침 후에도 가이드 설정만 복원된다.
- 모든 노출 카드가 출처명·URL·확인일을 가진다.
- 신규 집중 테스트와 문법 검사를 통과한다.
- 기존 사용자 변경 파일은 스테이징·수정하지 않는다.
