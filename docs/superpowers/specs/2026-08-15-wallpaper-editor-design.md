# 일정·성장 월페이퍼 편집기 설계

## 결정과 목표

기존 이중 이미지 설계는 사진 전체를 보존하려고 선명한 원본에 `object-fit: contain`을 적용했다. 그 결과 세로 사진이 카드 오른쪽의 좁은 띠처럼 보였고, 흐린 배경도 사용자가 기대한 휴대폰 월페이퍼 경험을 만들지 못했다.

이 설계는 `2026-08-15-wallpaper-dual-layer-design.md`를 대체한다. 일정·성장 카드는 한 장의 선명한 사진으로 완전히 채우고, 사용자가 휴대폰 배경화면처럼 사진의 위치와 확대 비율을 직접 조절해 저장한다.

## 사용자 경험

- 월페이퍼가 없을 때 `사진 변경`을 누르면 사진을 선택한 뒤 편집기를 연다.
- 월페이퍼가 있을 때 `사진 변경`을 누르면 현재 사진과 저장된 위치·확대값으로 편집기를 연다.
- 편집기 안의 `다른 사진 선택`으로 원본을 교체할 수 있다.
- 미리보기는 대상 카드 비율을 그대로 사용한다. 일정과 성장은 서로 다른 카드 비율과 편집값을 가진다.
- 사진은 항상 미리보기를 빈틈없이 채운다. 사용자는 한 손가락 드래그로 위치를 바꾸고, 두 손가락 핀치 또는 확대 슬라이더로 1배부터 3배까지 조절한다.
- `초기화`는 중앙 위치와 1배 확대 상태로 되돌린다.
- `취소`는 사진과 편집값을 모두 변경하지 않는다.
- `적용`은 사진을 바꿨다면 사진과 편집값을 함께 저장하고, 기존 사진을 조정했다면 편집값만 저장한다.
- 카드의 `삭제`는 기존처럼 사진과 편집값을 함께 제거한다.

## 화면 구조

`index.html`에 하나의 공용 월페이퍼 편집 다이얼로그를 추가한다. 일정·성장 카드가 같은 편집기를 사용하되 다이얼로그 상태에 `surface`를 보관한다.

편집기는 다음 요소로 구성한다.

- 제목과 대상 안내
- 대상 카드 비율의 미리보기 프레임
- 드래그·핀치가 가능한 선명한 사진
- 확대 슬라이더와 현재 배율
- `다른 사진 선택`, `초기화`, `취소`, `적용` 버튼

카드 렌더링에서는 기존 흐린 배경 이미지 요소를 제거한다. 단일 `.wallpaper-image`가 `object-fit: cover`로 카드를 채우며, 저장된 위치와 확대값을 CSS 사용자 정의 속성으로 적용한다. 텍스트 가독성 스크림, 콘텐츠, 사진 버튼은 이미지 위에 유지한다.

## 편집 상태와 좌표

월페이퍼 한 항목은 다음 값을 가진다.

```js
{
  path,
  url,
  positionX, // 0..100, 기본 50
  positionY, // 0..100, 기본 50
  zoom       // 1..3, 기본 1
}
```

드래그는 프레임 안에서 이동한 거리를 프레임 크기에 대한 백분율로 변환해 `positionX`와 `positionY`를 갱신한다. 값은 0..100으로 제한한다. 핀치는 두 포인터 사이 거리 변화를 사용하고, 슬라이더와 동일한 1..3 범위로 제한한다. 카드와 편집기 미리보기는 같은 렌더링 함수를 사용해 저장 전후 결과가 일치해야 한다.

## 저장과 가족 데이터 격리

`household_wallpapers`에 다음 열을 추가한다.

- `position_x numeric not null default 50`, 범위 0..100
- `position_y numeric not null default 50`, 범위 0..100
- `zoom numeric not null default 1`, 범위 1..3

기존 행은 기본값으로 중앙 `cover`가 적용된다. 가족·surface 복합 기본 키와 기존 RLS 정책은 그대로 유지한다. 조회 시 현재 가족의 행만 사용하고, 저장 시 현재 가족 ID와 `calendar` 또는 `growth` surface를 계속 강제한다. 사진 경로도 기존 가족별 Storage 경로를 유지한다.

로그인하지 않은 테스트 모드는 같은 값을 로컬 저장 객체에 보관한다. 로그인 상태에서는 사진 변경 시 Storage 업로드와 DB upsert를 수행하고, 위치만 조정할 때는 DB의 세 편집 열만 업데이트한다. 다른 가족의 데이터나 일정·성장 간 편집값을 섞지 않는다.

## 오류 처리

- 파일 형식과 10MB 제한은 편집기를 열기 전에 기존 검증을 재사용한다.
- 새 사진 미리보기 로딩에 실패하면 적용을 막고 사진을 다시 선택하게 한다.
- 사진 업로드가 실패하면 DB를 변경하지 않고 편집기를 유지한다.
- 업로드 후 DB 저장이 실패하면 새 Storage 파일을 정리하고 기존 월페이퍼를 유지한다.
- 위치만 저장하다 실패하면 카드 상태를 바꾸지 않고 편집기를 유지한다.
- 카드 이미지 로딩이 실패하면 기본 카드로 복구하고 같은 서명 URL을 반복 요청하지 않는다.

## 제거할 기존 경로

- `.wallpaper-backdrop` DOM 요소와 이중 이미지 URL 동기화 로직
- 블러·저채도 배경 CSS
- 선명한 이미지의 `object-fit: contain` 규칙
- 이중 이미지 전용 실패 처리와 테스트

별도 호환 레이어는 두지 않는다. 기존 DB 행은 새 열의 기본값만 받아 새 단일 `cover` 렌더링을 사용한다.

## 검증 기준

- 세로·가로 사진 모두 카드 전체를 빈틈없이 채우고 좁은 띠나 블러 복제본이 보이지 않는다.
- 일정·성장별 드래그 위치와 확대값이 저장 후, 새로고침 후, 다른 가족 기기에서도 동일하게 복원된다.
- 핀치와 슬라이더가 같은 확대 상태를 조작하며 1..3 범위를 벗어나지 않는다.
- 취소는 기존 사진과 편집값을 보존하고 초기화는 중앙 1배로 돌아간다.
- 기존 월페이퍼는 별도 사용자 작업 없이 중앙 `cover`로 표시된다.
- 사진·편집값은 현재 가족과 해당 surface에만 저장된다.
- 화이트·다크 모드에서 카드 텍스트와 버튼이 읽기 쉽고 조작 가능하다.
- 390×844 모바일 화면에서 일정·성장 편집기와 실제 카드 결과를 확인한다.
- 전체 정적 검사와 테스트, Supabase 스키마 검증, GitHub Pages 공개 자산을 확인한다.
