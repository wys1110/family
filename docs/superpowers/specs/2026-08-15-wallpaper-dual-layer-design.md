# 일정·성장 월페이퍼 이중 이미지 레이어 설계

## 문제와 목표

현재 월페이퍼는 원본 사진을 자르지 않는 `contain` 방식이라 세로 사진이 카드 오른쪽의 좁은 띠로 표시된다. 사진 전체는 유지하면서도 일정·성장 카드 전체가 한 장의 월페이퍼처럼 자연스럽게 보이도록 개선한다.

## 검토한 방식

1. 단일 `cover`: 카드 전체를 선명하게 채우지만 사진 일부가 다시 잘리므로 제외한다.
2. 단일 `contain`: 사진 전체를 보존하지만 현재처럼 빈 영역이 커지므로 제외한다.
3. 이중 이미지 레이어: 같은 사진의 흐린 확대본으로 카드를 채우고, 그 위에 선명한 원본 전체를 표시한다. 사진 보존과 시각적 완성도를 함께 만족하므로 선택한다.

## 선택한 디자인

- 카드 가장 아래에 같은 사진을 `object-fit: cover`로 확대하고 블러·어둡기 처리를 적용한 배경 이미지 레이어를 둔다.
- 그 위에는 현재처럼 `object-fit: contain`, `object-position: right center`인 선명한 원본 이미지 레이어를 유지한다.
- 텍스트 가독성 그라데이션은 두 이미지 위, 카드 콘텐츠 아래에 둔다.
- 일정 카드에서 월페이퍼가 있으면 기존 가족 캐릭터는 계속 숨긴다. 가족 이름 칩은 유지한다.
- 성장 카드도 동일한 두 이미지 구조를 사용하며 프로필, D-DAY, 사진 변경·삭제 버튼은 항상 이미지보다 위에 둔다.
- 블러 배경은 사진의 빈 영역만 자연스럽게 채우는 용도이며 원본보다 시각적으로 강하지 않도록 낮은 밝기와 채도를 적용한다.

## 구성과 데이터 흐름

각 카드에 장식용 배경 이미지와 원본 이미지 요소를 둔다. `renderWallpapers()`는 두 요소에 동일한 서명 URL을 설정한다. 원본 이미지 로딩 성공 여부를 월페이퍼 상태의 기준으로 사용하고, 원본이 실패하면 두 이미지를 모두 숨기고 기본 카드로 복구한다. 같은 실패 URL은 반복 요청하지 않으며 새 URL이 공급되면 두 레이어를 다시 시도한다. 배경 이미지만 실패하면 선명한 원본은 계속 표시한다.

Supabase 테이블, Storage 경로, 가족별 접근 제어, 업로드·삭제 흐름은 변경하지 않는다.

## 변경 범위

- `index.html`: 일정·성장 카드에 배경용 이미지 요소 추가
- `app.js`: 동일 URL을 두 이미지에 동기화하고 실패 상태를 관리
- `family-wallpapers.css`: 배경 cover·blur, 원본 contain, 스크림과 콘텐츠 적층 정의
- 관련 회귀 테스트와 정적 자산 버전 갱신

## 제외 범위

- 사진 자르기·확대·초점 위치를 사용자가 직접 편집하는 기능
- 카드 높이와 정보 구조의 전면 변경
- DB 마이그레이션과 기존 가족 사진 재처리

## 검증 기준

- 세로·가로 사진 모두 선명한 원본이 잘리지 않고 전체 표시된다.
- 카드 전체 배경은 동일 사진의 흐린 확대본으로 채워져 검정색 빈 띠가 두드러지지 않는다.
- 일정·성장 카드의 텍스트와 버튼이 읽기 쉽고 조작 가능하다.
- 월페이퍼가 있는 일정 카드에서는 기본 가족 캐릭터가 사진을 가리지 않는다.
- 원본 이미지 실패 시 기본 카드로 복구되고 같은 URL을 반복 요청하지 않는다.
- 배경 이미지만 실패해도 원본 사진과 콘텐츠는 유지된다.
- 전체 정적 검사와 테스트, 모바일 공개 화면 자산 버전을 확인한다.
