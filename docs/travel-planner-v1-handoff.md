# 가족 여행 일정표 V1 — 루나 구현 전달서

설계 기준일: 2026-09-23. 설계 확정 / 구현 및 서비스 연결 검증은 별도.

## 1. 목표와 범위

트리플의 일정 작성 방식처럼 가족이 장소를 담고 날짜별 순서를 편집하며 실제 지도에서 확인한다. 여행 전 계획이 여행 후 기록으로 그대로 남는다. 다른 앱의 디자인이나 자산을 복제하지 않고 기존 우리 가족 앱의 디자인을 따른다.

V1 필수: 여행 생성·수정, 장소 검색, 직접 핀 지정, 보관함, 날짜별 장소·메모, 순서 변경, 날짜 이동, 방문 체크, 가족 공동 저장, 오류·충돌 처리.

V1 제외: 항공·숙소 상품 검색/예약, AI 추천, 자동 동선 최적화, 이동시간 계산, 비용 정산, 사진 업로드, 공개 공유 링크, 오프라인 편집. 항공 시간은 메모로 입력하고 숙소는 일반 장소로 추가한다. 기존 사진·후기 등 자료는 삭제하지 않는다.

## 2. 화면

### 여행 목록
- 예정/진행 중과 지난 여행을 구분한 카드 목록. 오늘은 여행지 시간대 기준.
- 카드: 제목, 여행지, 기간, 장소 수. 탭하면 일정 편집 화면으로 바로 진입.
- 생성: 여행지 검색 가능한 드롭다운, 시작일, 종료일. 제목은 여행지 + 가족여행으로 자동 생성하고 수정 가능.
- 목록에 없는 여행지는 검색 또는 직접 입력 + 지도 중심 선택. 여행지 시간대는 확인 가능한 기본값을 제안하고 수정 가능하게 한다. 임의로 모두 한국 시간대로 지정하지 않는다.

### 일정 편집 — 모바일 기준
- 상단: 뒤로, 제목·기간, 가족 공유/저장 상태, 여행 설정.
- 날짜 탭: 보관함 / 전체 / DAY 1 / DAY 2 … 실제 날짜를 함께 표시.
- 실제 지도: 기본 높이 약 240px, 접기·확대 버튼. 확대하면 지도 전용 화면이며 돌아오면 날짜·스크롤 유지.
- 아래 일정 카드 목록. 화면 하단: 장소 추가 / 메모 추가. iPhone safe area와 키보드 영역을 침범하지 않는다.
- 기본 선택: 진행 중이면 오늘, 그 외 DAY 1. 기기에 저장된 유효한 마지막 선택이 있으면 우선 복원.
- 전체: 날짜별 묶음과 날짜별 색상. 서로 다른 날짜 사이에는 연결선을 그리지 않는다.
- 보관함: 날짜 미정 장소만 표시. 순서 연결선은 없다.

### 장소 추가
1. 이름 입력 후 검색 버튼. 첫 버전은 타이핑할 때마다 API 호출하지 않는다.
2. 최대 10개 결과: 이름·주소·종류와 위치 미리보기. 결과 없음/오류/한도 초과를 서로 구분.
3. 결과 선택 → 지도 위치 확인 → 날짜 선택 → 추가. 현재 날짜를 기본값으로 사용, 전체에서는 날짜 선택 필수.
4. 못 찾으면 지도 이동 후 중앙 핀 확정 + 장소 이름 입력. 위도·경도 수동 입력 UI 금지.
5. 위치 없는 텍스트는 메모로 저장하며 가짜 좌표를 만들지 않는다.
- 동일 날짜에 같은 장소를 넣으면 중복 안내 후 재방문으로 추가할 수 있다. 다른 날짜의 재방문은 허용.
- 현재 위치는 사용자가 버튼을 누른 경우에만 권한 요청.

### 카드·편집
- 장소 카드: 지도와 같은 번호, 이름, 선택 시간, 선택 메모, 방문 여부, 더보기.
- 지도 핀 선택 ↔ 카드 강조/스크롤 연결. 저장할 때 전체 지도를 다시 만들지 않는다.
- 더보기: 수정, 다른 날짜로 이동, 보관함으로 이동, 삭제.
- 명시적 순서 편집 모드에서 드래그 손잡이 제공. 위/아래 버튼도 제공하여 터치·키보드로 대체 가능.
- 일반 스크롤 중 드래그를 시작하지 않는다. 이동 후 도착 날짜 끝에 배치하고 재정렬 가능.
- 시간 미입력 허용. 시간 수정이 사용자가 정한 순서를 자동 변경하지 않는다.
- 메모 카드: 제목·본문·선택 시간. 낮잠/수유/항공시간 등을 입력. 지도 핀과 번호를 만들지 않는다.
- 장소 삭제는 확인 후 실행, 취소 시 아무 변경 없음. 여행 삭제는 V1에서 보관 처리로 구현하고 복원 가능하게 한다.
- 방문 체크는 자동이 아니라 사용자 명시 동작. 체크하지 않아도 날짜가 지난 여행은 기록으로 남는다.

## 3. 지도와 검색 — 결정

- Leaflet + Geoapify 래스터 지도 타일. Leaflet 버전 고정, 필요한 자산은 여행 탭 최초 진입 때만 로드.
- 이름/주소 검색: Geoapify Geocoding. 주변 분류 검색을 추가한다면 Places API로 분리하며 V1 필수 아님.
- Geoapify 무료 플랜으로 시작: 공식 가격표 확인 시 3,000 credits/day, 최대 5 requests/sec. 크레딧은 검색 횟수와 같지 않고 타일 요청도 소비한다. 무제한 무료를 약속하지 않는다.
- 카드/핀에는 사용자가 확인한 장소 스냅샷과 좌표 저장. 공급자·place ID·출처를 함께 남긴다.
- 지도에 Geoapify/OSM 출처 표시 유지. 공급자 필드를 두어 추후 교체 가능하게 한다.
- 검색은 인증된 서버 프록시 경유. 사용자·프로젝트 요청 제한과 짧은 검색 캐시 적용. 검색용 키는 서버 secret에만 보관.
- 타일용 브라우저 키는 별도로 분리, 허용 도메인 제한. Android WebView origin은 따로 검증. 제한을 없애 해결하지 않는다.
- 응답 대기 중 새 검색 시작 시 이전 응답 폐기. 가족 전환 시 진행 중 요청도 취소/무효화.
- 연결선은 장소 순서를 잇는 직선이며 항상 '방문 순서 · 실제 이동 경로 아님' 표시. 메모는 연결선에 영향 없음.
- 길찾기는 선택한 두 장소의 좌표를 이용한 외부 지도 링크로 연다. 다중 경유지 제한을 피하고 실제 이동시간을 추정 표시하지 않는다.
- 지도 로딩 실패 시 일정 목록은 사용 가능. 검색 실패 시 입력 보존, 재시도 제공. 지도도 불가하면 위치 없는 메모만 허용.
- 한국어/일본어 POI 품질은 아직 실측하지 않았다. 키 설정 후 오키나와 숙소·음식점·관광지 및 국내 장소로 검증한다. 검색 기능을 주소 검색만으로 충족했다고 보고하지 않는다. 품질이 부족하면 결과를 보고하고 공급자 변경은 별도 결정한다.

## 4. 데이터와 저장

첫 버전은 여행 한 개당 DB 행 한 개로 저장한다. 가족의 모든 여행을 하나의 JSON으로 덮어쓰지 않는다.

제안 테이블 `family_trips`:
- id UUID, household_id UUID FK, title(1..60), destination_label(1..120), center_lat/lng(둘 다 null 또는 유효 좌표), timezone(IANA), start_date, end_date
- document JSONB, revision bigint(server-managed), created_by, updated_by, created_at, updated_at, archived_at
- document = {schemaVersion: 1, items: [], legacy: {}}. 기존 기록의 보존용 legacy는 화면에서 읽기 가능해야 한다.
- item = {id: UUID, type: place|note, dayIndex: null|0..N-1, order: integer, title, time: null|HH:mm, note, visited: boolean, place: null|{provider, providerId, name, address, lat, lng, attribution}}
- 장소 항목은 유효한 좌표 필수. 메모는 place=null. 이름 120자, 메모 2,000자, 여행 366일, 항목 500개까지 서버에서도 검사.
- 날짜는 여행지의 날짜 문자열로 취급하고 UTC 변환으로 하루가 바뀌지 않게 한다. dayIndex가 실제 날짜와 분리되어 출발일 변경 시 일차 순서를 유지한다.
- 순서는 각 날짜 안에서 연속 정수로 정규화. 번호는 장소에만 부여하며 지도/목록이 동일한 파생 함수를 사용.
- 기기별 상태(선택 날짜·스크롤·지도 중심·줌)는 DB 문서에 넣지 않는다.

### 날짜 변경
- 출발일 변경: 일차별 계획을 함께 이동하며 변경 미리보기 후 저장.
- 기간 단축: 범위 밖 항목 개수 안내. 사용자 동의 시 보관함으로 이동하며 이전 날짜를 보존, 동의 없으면 변경 취소.
- 메타데이터와 항목 이동을 한 트랜잭션으로 처리. 일부만 저장되는 상태 금지.

### 동시 수정·신뢰성
- 모든 변경은 `saveTrip(id, expectedRevision, mutationId, nextDocument/metadata)` 계약을 거친다. create는 별도, 삭제는 archive 동작.
- 서버에서 해당 행을 잠그고 가족 권한·revision·입력 검증 후 한 번에 저장, revision 증가. 재시도 mutationId는 멱등 처리.
- revision 충돌이면 저장 거부, 최신 내용과 내 편집 초안 유지. '최신 불러오기'와 '내 초안 복사' 제공. 자동 강제 덮어쓰기 금지.
- 응답 유실 시 mutationId 저장 여부를 조회해 성공/실패를 판별. 연타 방지와 요청 중 버튼 상태 제공.
- 완료 표시는 서버 성공 응답 이후만. 실패하면 초안 유지. 작성 폼이 실시간 갱신으로 사라지지 않게 한다.
- 가족 공유 갱신: 여행 상세의 관련 행 Realtime 구독 + 앱 복귀 시 재조회. 재연결 실패 표시, 편집 중 최신 변경은 알림만 제공.
- V1 오프라인은 마지막 기록 읽기만. 새 편집을 공유 저장처럼 표시하지 않는다.

## 5. 가족 권한

- 기존 household_members를 원본으로 가족 가입 여부 확인. 클라이언트 household_id 값만 신뢰하지 않는다.
- 해당 가족의 기존 권한 모델을 확인하고 일반 편집 구성원이 공동 편집. 기존 읽기 전용 역할을 임의로 승격하지 않는다.
- 테이블 RLS 활성화, SELECT/INSERT/UPDATE 각각 정책, UPDATE에는 USING/WITH CHECK 모두 설정. 가족 소속 변경 금지.
- 서버 함수도 호출자 권한 및 RLS를 지킨다. SECURITY DEFINER로 권한 오류를 우회하지 않는다. 프론트에 service_role/secret 노출 금지.
- 로그아웃·가족 전환 때 구독·초안·조회 캐시 분리/정리. 이전 가족 요청의 늦은 응답을 새 화면에 반영하지 않는다.
- 현재 운영 DB에 필요한 테이블이 없다고 확정된 것은 아니다. 이전 확인은 로컬 파일 검색뿐이었다. 구현자는 운영 스키마를 읽기 전용으로 확인 후 충돌 없는 마이그레이션을 준비한다.

## 6. 기존 구현과 이관

관련 파일: travel.js / travel.css / travel-map.js / travel-data.js / config.js / test/travel-tab.test.js. 기존 프레임워크 없는 JS 구성 유지, 전체 앱 재작성 금지.

로컬에는 미완성 travel-sharing.js 및 비동기 travel-data.js 변경이 있다. 원격 배포본과 동일하다고 가정하지 말고 main과 diff를 확인한다. 기존 작업을 덮어쓰거나 실수로 함께 배포하지 않는다.

- 기존 로컬 여행은 자동 삭제/자동 공유하지 않는다. 가족 소속 확인 후 '이 기기의 여행 가져오기'로 미리보기·확인 후 이관.
- 원래 여행 ID와 household 조합으로 중복 이관 방지, 서버 저장 검증 후에도 원본 보존.
- items.localDate를 dayIndex로 변환. 좌표 없는 기존 장소는 삭제하지 않고 '위치 미지정'으로 표시하며 핀 추가 가능.
- memories/expenses/bookings/candidates/tasks 등 기존 필드는 legacy에 보존. 별도의 기존 기록 보기에서 조회 가능하게 한다.
- 여행 소개가 신규 생성 시 누락되는 기존 문제, 날짜 파싱/정렬, 키보드 닫기/포커스 복원도 검토.
- config 및 JS/CSS 자산 버전 갱신. index.html의 config URL도 변경하고 관련 테스트 기대값 동기화. PWA 캐시 갱신을 실제로 검증.
- 새 DB가 준비되지 않으면 기존 앱 유지. 가족 공유를 기기별 저장으로 조용히 대체하고 완료라고 보고하지 않는다.

## 7. 구현 순서와 완료 기준

1. 원격/로컬 상태와 실제 스키마 확인 → 데이터 계약·권한·동시 수정 테스트.
2. 실제 지도/검색 연결 → 한국어·일본어 장소 실측. 필요한 키가 없으면 이 단계만 명확히 차단 표시.
3. 모바일 일정 화면 → 보관함/편집/날짜 이동/방문 체크.
4. 공동 저장·충돌·오류·기존 자료 이관.
5. 데모 모드 + 실제 서로 다른 두 계정 검증 → 배포 가능한 변경만 분리.

필수 인수 테스트:
- 여행 생성 → 장소 3개 담기 → 순서 변경 → 날짜 이동 → 재접속 후 유지.
- 날짜 미정 보관함, 같은 장소 재방문, 장소 없는 메모 정상 처리.
- 실제 지도와 카드 번호/선택 동기화. 검색 실패/지도 실패에도 기록 유실 없음.
- 375px/390px 모바일 화면, iOS PWA, Android WebView에서 입력·스크롤·지도 터치·safe area 검증.
- 두 가족 계정 공동 편집 확인, 서로 다른 가족·비로그인 읽기/쓰기 거부.
- 같은 revision 동시 저장 시 한 요청만 성공, 다른 초안 유지. 네트워크 응답 유실·중복 제출 처리.
- 날짜 이동·기간 단축 후 기록 보존. 잘못된 좌표/날짜/과도한 문서 서버 거부.
- 기존 여행 이관 두 번 실행해도 중복 없음, 원본과 기존 메모 유지.
- 데모 데이터와 실제 가족 데이터 완전 분리.
- 저장은 빠르게 피드백하되 서버 승인 이전 '저장 완료' 금지. 자동 테스트 통과 외 실제 UI 증거 필요.

## 8. 루나에게 전달할 지시

이 문서를 구현 기준으로 사용한다. 범위를 임의 축소하거나 항공·숙소 검색을 복원하지 않는다. 미완성 공유 코드와 운영 스키마부터 확인한다. 작동하는 한 단계씩 구현하고 결과/테스트/미해결 사항을 보고한다. API 키·DB 권한이 없으면 완료를 주장하지 않고 필요한 설정만 요청한다. 키 발급·유료 전환·운영 DB 변경·공개 배포는 별도 승인 범위로 관리한다. 코드 작성/검증은 진행하되 배포 전 구체적 변경과 검증 결과를 제시한다.
