# Startup loading improvement

Start bootstrap data reads while optional modules load. Preserve the existing bounded module wait before final rendering and familycontextchange. Skip the preliminary startup render that would otherwise overwrite a saved non-core tab before its module installs. Normal later account/family changes still clear the previous household immediately.

Allow only previously network-forced, versioned, same-origin public JS/CSS to reuse HTTP cache. Keep config.js and unversioned files network-only. Query-string versions remain separate cache keys. No caching of API responses or family photos was added. Deployment must continue bumping modified asset versions.

Validation: 448 tests passed; npm run check passed. Browser comparison used local demo data with an injected 750 ms bootstrap delay (simulated database latency), three fresh contexts per version. Median initial readiness: baseline 3,461 ms; changed 2,947 ms. This is a controlled local scenario, not a measurement on the user's iPhone. All 60 module scripts loaded and there were no page errors. An earlier preload-only experiment showed no meaningful gain and was removed.

Real service-worker/browser-cache check: fetching motion-system.js?v=cache-check-a twice resulted in one HTTP server request; changing to v=cache-check-b resulted in another request. Fetching config.js twice resulted in two server requests, preserving manifest freshness.
