# Family 기록 처리 속도 개선

디자인과 데이터 구조는 유지하고, 기록 목록 조작과 일정 갱신에서 불필요한 성장 화면 계산을 제거했다. 첫 화면의 네트워크 로딩 속도가 빨라졌다는 근거는 없다.

## 변경

- 기록 종류·기간·전체/오늘·초기화·100개 더보기는 목록과 필터만 갱신한다. 전체 요약·돌봄 패턴·사진·성장 측정은 재계산하지 않는다.
- 일정 화면을 갱신할 때 성장 기록을 계산하지 않는다. 성장 탭 직접 진입, 저장된 성장 탭 복원, 성장 화면 데이터 갱신은 최신 상태를 렌더한다.
- 최신 성장 측정은 전체 정렬 대신 한 번 순회한다. 같은 시각은 기존처럼 첫 기록을 선택한다.
- 사진이 있는 기록만 정렬한다. URL/썸네일 대응, 최근 4장, 전체 앨범, 부분 목록 갱신 후 사진 오류 복구를 유지한다.
- 영구적인 파생 데이터 캐시를 추가하지 않는다. 같은 배열의 수정·추가와 사진 URL 갱신에도 현재 데이터를 읽는다.

## 브라우저 비교

기준은 main `692d2670de8ad08578f770a87b564a2b2829ae45`. 로컬 Codex 브라우저의 390×844 iframe을 1280×900 화면 안에 표시하고 기준/변경 버전을 번갈아 3회 실행했다. 각각 준비 렌더 1회 뒤 5회 측정했으며, 아래 수치는 각 회차 중앙값 3개의 중앙값이다. 동일한 500일 범위의 수유·기저귀·수면·성장·건강·첫 순간 합성 기록을 사용했다. 사진 URL은 비웠고 전체 목록은 양쪽 모두 100개를 표시했다. 실제 가족 데이터·인증 API·저장은 사용하지 않았다.

동기 JavaScript 실행 시간(ms):

| 기록 수 | 성장 전체 | 전체→오늘 필터 | 일정 전체 갱신 |
|---|---:|---:|---:|
| 1,000 | 7.5 → 6.0 | 6.9 → 2.2 | 7.0 → 2.4 |
| 5,000 | 16.6 → 15.1 | 15.9 → 3.1 | 17.1 → 2.3 |
| 10,000 | 29.2 → 24.7 | 28.5 → 4.0 | 31.0 → 2.3 |

두 번의 animation frame까지 포함한 시간(ms):

| 기록 수 | 성장 전체 | 전체→오늘 필터 | 일정 전체 갱신 |
|---|---:|---:|---:|
| 1,000 | 49.5 → 42.9 | 33.5 → 32.8 | 33.2 → 33.3 |
| 5,000 | 53.0 → 56.2 | 48.4 → 33.1 | 41.0 → 33.3 |
| 10,000 | 67.9 → 66.9 | 67.1 → 33.0 | 53.3 → 33.4 |

1만 개에서 필터 계산은 약 86%, 일정 계산은 약 93% 줄었다. 성장 전체 화면의 그리기 시간은 큰 개선을 주장하지 않는다. 일정 갱신의 수면 분할 호출은 5회에서 0회로 줄었으며, 실제 성장 전체 갱신은 기존 5회를 유지한다.

초기 달력 준비 중앙값은 382.5 → 349.6ms, 첫 여행 탭 준비는 54.4 → 57.0ms였다. 표본이 작고 변동 폭이 겹치므로 로딩 개선으로 해석하지 않는다. 전송 자산과 지연 모듈 순서는 변경하지 않았다. 실제 휴대폰 CPU·Safari·이동통신 및 실계정 데이터 읽기 지연에 대한 결과도 아니다.

원시 결과: [브라우저 측정 JSON](2026-10-13-speed-results.json). 측정 harness 원본은 로컬 `/tmp/family-speed-20261013/{server.py,controller.html,bench.js}`에 있으며 데모 모드 확인, fixture 및 필터/탭/spy 원상복구를 포함한다.

## 검증

- 전체 111개 파일 / 596개 테스트, `npm run check`, 변경 문법과 diff 검사를 통과했다.
- 실제 코드에서 달력 숨김 계산, 성장 직접 진입·저장 탭·데이터 갱신, 필터/기간/ARIA/빈 상태/초기화, 100→200개 더보기, 최신 원본 ID 편집, 사진 순서·복구를 검증한다.
- 로컬 실제 wrapper stack에서 첫 성장 진입과 저장된 성장 탭 재로드를 확인했다. 도담 프로필·9개 원본 기록·100mL/직수36분/수면82분 요약이 표시된다. 기간+수면 필터는 2개 기록이며 요약과 시계 DOM은 바뀌지 않는다. 자정을 넘는 수면 목록의 수정 창은 원본 395분을 표시한다. 잘못된 기간은 0개·ARIA 오류·안내를 표시하고 초기화하면 9개로 돌아온다.
- 설정·동화·여행·일정·성장 복귀와 다크 테마 전환을 실제 UI로 확인했다. 390/320px의 가로 넘침 없음, console warning/error 0. 검증용 로컬 데모이며 기록 저장은 하지 않았다.
- 앱 CSS·색·폰트·아이콘 및 원본 기록/네트워크/인증 구조는 변경하지 않았다.
- 실제 휴대폰·인증된 저장/동기화와 카카오 지도 연결은 이 변경의 검증 범위가 아니다.
