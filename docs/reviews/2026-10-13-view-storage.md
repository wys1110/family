# 탭 복원과 데모 저장 범위

속도 개선 공개 화면 검증에서 데모의 성장 탭을 선택한 후 새로고침하면 예전 설정 탭으로 돌아가는 현상을 확인했다. core는 데모용 `ACTIVE_VIEW_KEY`를 사용하지만 일부 확장 탭은 실제 앱용 키를 직접 읽거나 쓰고 있었다. 공개 브라우저에는 실제 앱용 설정 선택값과 데모용 성장 선택값이 함께 존재하는 상황이었다.

settings·기능 요청·관리·탭 라벨·동화·지연 탭을 core의 `ACTIVE_VIEW_KEY`로 통일했다. 데모의 실제 앱 키 중복 쓰기와 동화의 별도 기본 키를 제거했다. 이전 선택값을 이관하거나 다른 키로 되돌리는 경로는 추가하지 않는다. 실제 앱은 기존 키를 계속 사용하며, 기록·인증·디자인은 변경하지 않는다.

수정 전 VM으로 `live=settings`, `demo=growth`의 잘못된 설정 복원을 재현했다. 신규 회귀 검사 5개로 데모/실제 앱 각각의 설정 복원과 지연 탭 저장 범위를 확인했다. 전체 112개 파일 / 601개 테스트, `npm run check`, 변경 JS 문법과 diff 검사를 통과했다.

로컬 실제 브라우저에서는 기존 모듈로 설정→성장을 선택해 키가 섞인 조건을 만든 뒤 새 코드로 재로드했다. 성장 탭·도담 프로필·새 settings/config 버전이 복원됐다. 검증은 데모에서만 진행했으며 실제 가족 기록은 수정하지 않았다.
