# 가족 수면 동기화와 슬라이드 삭제

2026-10-31 사용자 요청: 수면 시작/종료를 가족 모두에게 동기화하고, 검토한 슬라이드 삭제 시안을 적용한다. 정기 보안 점검과 별개의 기능 요청이다.

## 동작

- 로그인한 같은 가족은 아기별 공용 수면 타이머를 사용한다. 시작 시각을 공유하고 다른 가족도 종료할 수 있다. Realtime 변경 시 조회하며, 앱 복귀/온라인 복구와 화면이 열린 동안 15초 간격으로 누락된 변경을 재확인한다. 앱을 닫은 사용자에게 별도 푸시를 보내는 기능은 아니다.
- 서버는 아기 행 잠금과 활성 수면 유일 인덱스로 시작 충돌을 처리한다. 시작 요청 ID 별 대응 관계도 저장해 동시 시작 후 응답이 유실돼도 종료된 수면을 다시 시작하지 않는다.
- 종료와 성장 기록 생성은 하나의 트랜잭션이며 기록 ID는 수면 ID다. 재시도는 최초 종료 결과를 반환하고, 삭제된 기록을 다시 만들지 않는다. 한국 시간 기준으로 기록 날짜와 시간을 저장하며 기존 수면 기록의 24시간 상한을 유지한다.
- 기기에 남은 진행 중 수면은 기존 시작 시각으로 가져온다. 이미 종료하고 저장을 기다리는 구버전 기록과 로컬 수유 타이머는 기존 처리로 보존한다. 데모 모드는 실제 DB를 사용하지 않는다.
- 성장 기록을 왼쪽으로 밀면 삭제 버튼이 열린다. 밀기 자체로 삭제하지 않으며 기존 확인창, 가족/계정 검사, 실패 시 기록 유지, 사진 참조 확인 후 정리 처리를 재사용한다. 키보드 왼쪽 화살표로 열고 Escape/오른쪽 화살표로 닫는다. 세로 스크롤과 핀치 확대를 허용한다.

## 접근 범위와 배포

- `family_sleep_sessions`는 RLS로 같은 가족의 SELECT만 허용한다. 직접 INSERT/UPDATE/DELETE와 익명 접근은 허용하지 않는다. 아기와 가족 복합 외래키를 사용한다.
- 쓰기는 명시적인 로그인·가족 소속·아기 소속 검사를 하는 비공개 스키마 함수와 공개 invoker RPC로 제한한다. 기존 테이블 권한과 다른 비공개 스키마 권한은 변경하지 않는다.
- 마이그레이션 `20261031094052_shared_family_sleep.sql`을 적용한 뒤 프런트엔드를 배포한다. 되돌릴 때는 먼저 프런트엔드를 이전 버전으로 되돌린다. 기존 가족 데이터나 새 수면 이력을 삭제하는 롤백은 하지 않는다.

## 검증

- PGlite에서 실제 마이그레이션의 테이블/RLS/RPC를 실행해 가족 두 명의 시작/종료, 중복·유실 재시도, 외부 가족/탈퇴자 차단, 직접 쓰기 차단, 취소, 기록 생성 실패의 트랜잭션 롤백, 자정 경과, 삭제 후 재시도를 검증한다. PGlite는 WAL publication을 지원하지 않아 publication 문만 제외한다.
- 실제 프런트 모듈을 독립된 두 클라이언트 컨텍스트에서 실행해 상태 공유, 재접속, 아기 전환, 구버전 타이머 가져오기, 계정 변경 중 늦은 응답 무시, 재시도 시 ID/시각 유지를 검증한다. 네트워크와 Realtime 전달은 모의 객체다.
- 전체 앱 데모 브라우저에서 슬라이드·확인 취소/삭제·키보드 조작·세로 방향 제스처·390/820/1280px 가로 넘침을 검증한다. 실제 가족 데이터는 테스트에 사용하지 않는다.
- 실제 가족 계정 두 대의 휴대폰을 이용한 동시 조작은 미검증이며 위 모의 테스트와 구분한다. DB 반영·CI·공개 배포 결과는 PR/실행 결과에서 별도로 확인한다.

설계 참고: [Supabase Postgres Changes](https://supabase.com/docs/guides/realtime/postgres-changes). 최신 변경 공지의 TLS 호환성 변경도 확인했으며 이 기능의 API 형태 변경은 필요하지 않았다.

## 2026-10-31 슬라이드 적용 누락 수정

- 첫 구현과 검증이 아래쪽 `최근 기록`의 `#growthList`에만 한정돼, 위쪽 `시간별 기록`의 수면·수유 카드와 측정 기록에는 슬라이드가 연결되지 않았다. 공개 데모의 `.care-time-row.sleep`을 밀어 삭제 버튼이 열리지 않는 실패를 직접 재현했다.
- 돌봄 시간별 목록·분리 카드·측정 기록·최근 기록에 동일한 동작과 원본 기록 ID를 연결했다. 각 목록의 독립적인 날짜/필터 재렌더 후에도 새 행을 처리한다. Nova의 투명한 시간별 카드 배경은 이동 중 삭제 영역이 비쳐 보이지 않도록 보정했다.
- 회귀 테스트는 네 기록 표시 유형, 원본 ID 전달, 재렌더 후 중복 래핑 방지, 세로 이동, 서로 다른 목록 간 열린 삭제 버튼 닫기를 다룬다. 전체 앱 브라우저의 터치 입력으로 시간별 수면·측정·최근 기록 각각에서 삭제 취소/확인을 검증한다. 실제 휴대폰 검증과는 구분한다.
