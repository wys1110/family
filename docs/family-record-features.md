# 기록 백업 · 진료 준비 · 성장 추억

현재 브랜치에서 구현·검증 완료. 이 기능 묶음은 운영에 아직 반영하지 않았습니다.

## 사용 화면

- 성장일기의 **진료 준비**: 날짜 범위(최대 92일)와 질문을 입력해 수유·수면·체온·기저귀, 최근 성장 측정, 건강 메모를 요약합니다. 인쇄 / PDF 저장 버튼은 브라우저 인쇄 기능을 엽니다. 질문은 화면을 닫으면 지워지고 서버로 보내지 않습니다.
- 성장일기의 **성장 추억**: 선택한 아기의 첫 순간과 사진 기록을 월별 카드로 표시합니다. 카드에서 기존 기록 편집으로 연결하고 첫 순간을 추가할 수 있습니다.
- 설정의 **백업과 복원**: 일정, 성장 기록, 아기 프로필, 캘린더 구성원, 가족 할 일과 성장 기록의 원본 사진을 JSON 한 파일로 보관합니다. 개인 할 일·프로필 사진·월페이퍼는 포함하지 않습니다.

## 데이터 처리

- 일정·성장 기록·할 일·Excel·백업 조회를 페이지별로 끝까지 읽습니다. 서버가 요청 크기보다 작게 제한해도 다음 페이지를 읽습니다. 중간 오류는 부분 백업으로 저장하지 않습니다.
- 페이지 조회는 데이터베이스 전체의 시점 고정 스냅샷은 아닙니다. 다운로드 도중 대량 수정·삭제를 피하는 것이 좋습니다. 반복된 페이지는 오류로 처리합니다.
- 사진은 원본 파일을 포함하고 SHA-256으로 손상 및 연결 누락을 확인합니다. 원본 사진 합계 50MB, 개별 사진 10MB, 전체 JSON 80MB까지 지원합니다. 한도 초과나 원본 다운로드 실패는 명확히 표시하며 사진을 조용히 누락하지 않습니다. 사진 제외 백업을 선택할 수 있습니다.
- 새 백업 형식은 v3이며 기존 v1/v2 파일을 읽을 수 있습니다. 복원은 현재 가족 관리자만 실행합니다. 새 DB 함수는 사진 경로·존재 여부를 확인하고 기록·할 일·중복 복원 등록을 한 트랜잭션으로 저장합니다. 기존 기록에 추가하며 덮어쓰지 않습니다.
- 사진 업로드와 DB 트랜잭션은 별개입니다. DB 복원 실패 시 업로드된 미연결 사진이 남을 수 있습니다. 콘텐츠 기반 경로를 사용하므로 같은 백업으로 재시도하면 기존 파일을 검증하고 재사용합니다. 모호한 네트워크 실패 직후 사진을 삭제하지 않습니다.
- 진료 요약의 평균은 해당 항목이 기록된 날짜 기준입니다. 미기록과 0을 구분하고 모유 수유량을 추정하지 않습니다. 수면 시작 시각이 있으면 날짜별로 배분하며, 없으면 기록일에 합산합니다. 진단·정상 범위 판정은 제공하지 않습니다.

## 검증

- 83개 테스트 파일, 425개 테스트 통과.
- 코드 문법·TypeScript·테마 색상 검사 통과.
- 새 테스트: 1,251건 페이지 조회, 낮은 서버 반환 한도, 중간 오류·가족 변경, 자정 수면·미기록 집계, HTML 이스케이프, 사진 중복·손상·누락, 실제 PostgreSQL 마이그레이션의 사진·할 일 복원, 반복 연결, 중복 방지, 트랜잭션 취소 및 권한 확인.
- Chromium에서 가상 가족 데이터로 모바일(390px)·데스크톱(1280px), 밝은 테마·어두운 테마를 확인했습니다. 브라우저 오류와 다이얼로그 가로 넘침이 없었습니다. 사진 1장과 가족 할 일 1건을 포함한 백업 다운로드 및 로컬 복원, 인쇄 문서 생성을 확인했습니다. 실제 iOS 인쇄 UI와 운영 가족 데이터 복원은 실행하지 않았습니다.

## 운영 반영 순서

1. 최신 main과 복원 관련 DB 스키마에 후속 변경이 있는지 확인합니다.
2. `supabase/migrations/20260913100952_backup_photos_and_todos.sql`을 적용합니다. 기존 복원 함수는 유지하고 `restore_household_backup_v3`를 추가합니다.
3. 검증된 코드·스타일·모듈 버전을 GitHub에 반영하고 Pages 검증 및 배포 결과를 확인합니다.
4. 신규 RPC 권한을 읽어서 확인합니다. 실제 가족 데이터로 복원 테스트는 하지 않습니다.
